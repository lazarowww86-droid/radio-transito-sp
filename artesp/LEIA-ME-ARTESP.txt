Produto aprovado: Ocorrências Rodoviárias

ATUALIZAÇÃO DE 13/10/2026 — SERVIÇO JÁ PUBLICADO
1. Extraia esta versão atualizada do pacote 11-INTEGRACAO-ARTESP.zip.
2. No GitHub, abra a raiz do repositório radio-transito-sp.
3. Em Add file > Upload files, arraste a pasta artesp inteira e confirme o commit.
4. O Cloudflare já conectado ao GitHub publicará a atualização automaticamente.
5. O serviço radio-transito-sp continua usando o segredo ARTESP_API_KEY já cadastrado.
6. Após o build concluir, será feita nova verificação em:
   https://radio-transito-sp.lazarowww86.workers.dev/boletins

CORREÇÃO DESTA VERSÃO
- A chamada fetch mantém o contexto global exigido pelo runtime do Cloudflare.
- O modo de redirecionamento é manual; a credencial não segue para outro endereço.
- O nome no arquivo wrangler.jsonc corresponde ao serviço publicado: radio-transito-sp.
- O pacote contém somente a pasta artesp. Música, podcasts, previsão e player permanecem nos arquivos atuais do site.

As etapas seguintes documentam a instalação completa para referência.

ETAPA 1 — ENVIAR A PASTA
1. Extraia 11-INTEGRACAO-ARTESP.zip no computador.
2. No GitHub, abra a raiz do repositório radio-transito-sp.
3. Use Add file > Upload files e arraste a pasta artesp inteira. Confirme o commit.
   A estrutura será artesp/worker.mjs, artesp/traffic.mjs, artesp/wrangler.jsonc etc.
   Este pacote acrescenta somente essa pasta. Os arquivos do player do pacote 10 continuam sendo usados.

ETAPA 2 — CRIAR O SERVIÇO NO CLOUDFLARE
1. Entre em https://dash.cloudflare.com/ e abra Workers & Pages.
2. Selecione Create application > Import a repository e conecte sua conta GitHub.
3. Escolha o repositório radio-transito-sp.
4. Configure os campos:
   Nome do Worker: radio-transito-sp
   Branch: main
   Path / Root directory / Diretório raiz: artesp
   Build command / Comando de compilação: npm run validate
   Deploy command / Comando de publicação: npm run deploy
5. Clique Save and Deploy e aguarde a publicação.
6. O armazenamento compartilhado ARTESP_CACHE será criado pela configuração do pacote.
   O projeto usa SQLite/Durable Objects, disponível no plano Free dentro dos limites da plataforma.

ETAPA 3 — GUARDAR A CHAVE
1. No portal https://ccm.artesp.sp.gov.br/, abra Minha Conta > Minhas APIs > Ocorrências Rodoviárias.
2. Abra a seção de Ocorrências e revele/copie sua chave ativa. O portal pode limitar a exibição desse valor.
3. No Cloudflare, abra o Worker radio-transito-sp > Settings > Runtime variables > Add variable.
4. Marque Production e a opção Secret.
   Key / Nome: ARTESP_API_KEY
   Value / Valor: cole somente a chave copiada do portal.
   O código já acrescenta o prefixo Api-Key. Esse prefixo não deve fazer parte do valor salvo.
5. Clique Add variable and deploy para aplicar.
   A chave fica no segredo do seu Worker. Ela não faz parte dos arquivos enviados ao GitHub.

ETAPA 4 — TESTAR E CONECTAR À RÁDIO
1. Copie o endereço HTTPS do Worker fornecido pelo Cloudflare.
2. Abra esse endereço no navegador. A página deve mostrar configured: true.
   Isso confirma a presença da configuração; ainda não testa a autorização da ARTESP.
3. Acrescente /boletins ao endereço e abra novamente.
   O resultado correto é um JSON com updated_at e items. Os registros da fonte aparecem no campo items.
   Havendo erro, use a mensagem retornada para conferir a chave, o produto, os termos ou a cota.
4. Para testar na rádio, abra Configuração da fonte de trânsito, cole o endereço completo terminado em /boletins e clique SALVAR FONTE.
   Essa configuração atual é local ao navegador. Para definir a fonte automaticamente para todos os ouvintes, envie somente o endereço público do Worker para a próxima atualização do site.
5. Com os dados válidos, o botão TESTAR BOLETIM faz a leitura. O boletim automático continua a cada 15 minutos de escuta; o player retoma do mesmo ponto.

ALCANCE E HORÁRIO
- Consulta o produto Ocorrências Rodoviárias, com registros ativos conhecidos nos últimos sete dias.
- O recorte inicial são rodovias monitoradas pela ARTESP nos municípios de São Paulo e Guarulhos.
- A consulta não substitui um painel de todas as ruas urbanas, nem fornece velocidade em toda a malha viária.
- updated_at é o horário que a API oficial informa para a consulta. O horário original não é renovado ao servir o cache.
- São escolhidos até cinco registros para a locução. Se houver mais de uma página ou algum registro descartado, complete será false.
- O adaptador não inventa detalhes de bloqueios nem interpreta campos de vítimas. A inclusão desses detalhes depende de examinar a resposta real após a conexão.

CACHE E COTA
- Em operação normal, uma consulta à ARTESP a cada 15 minutos, compartilhada pela rádio inteira.
- As tentativas ficam registradas antes da chamada e sobrevivem a reinícios.
- Falhas aguardam pelo menos 5 minutos e 1 segundo; 429 respeita Retry-After.
- Há um teto adicional de 12 tentativas em qualquer janela de uma hora.
- Essa proteção vale para este serviço. Usar a mesma chave em outros aplicativos também consome a cota da ARTESP.
- A rádio continua tocando se a fonte estiver indisponível. O serviço não apresenta dados de uma consulta antiga como dados novos.
